# 기획 → 이슈 쪼개기 (돌아올개 CRM)

검토가 끝난 기획 문서를 읽고 **한 사람이 브랜치 하나로 끝낼 수 있는 이슈**로 나눈다. 규칙의 기준은 `CONTRIBUTING.md`와 `CLAUDE.md`다.

## 절대 규칙

1. 기획에 없는 작업을 만들지 않는다. 필요해 보이면 `[제안]` 목록에 따로 모은다.
2. 모든 이슈는 ID를 가리킨다: `FR-…` → `POL-…` → `S-xx`/`B-xx` (예: `FR-CNT-001 → POL-TGT-006 → S-04`).
3. 우선순위는 요구사항 명세서의 P1/P2/P3를 그대로 쓴다. 완료 조건은 요구사항 명세서 '확인 방법' 칸과 정책 정의서에서 가져온다. 지어내지 않는다.
4. 담당자를 대신 정하지 않는다. `[?]`로 두고, 묶음 제안만 `[제안]`으로 한다.
5. 기획 문서와 결정판 값을 고치지 않는다. 빈칸 · 충돌은 '기획 보완 필요' 목록에 적는다.

## 입력

- `docs/planning/요구사항 명세서(*).md` (기능 · 우선순위 · 확인 방법 · 의존성 · 스프린트 범위)
- `docs/planning/정책 정의서(*).md` (숫자 · 조건 · 문구)
- `docs/planning/업무 분석_사용자(*).md`, `업무 분석_백오피스(*).md` (화면 ID · 흐름)
- `docs/design/DB 설계(*).md` (테이블)
- `frontend/README.md`, `backend/README.md` (담당 폴더 경로)
- 범위를 사용자에게 먼저 묻는다: 이번 스프린트만? P1만? 전체?

## 절차

1. **범위 확인**: 대상 스프린트 · 우선순위, 팀원 수. 착수를 막는 `🟥`·`[?]`가 있으면 먼저 알린다.
2. **#01 공통 기반 이슈**를 맨 앞에 둔다: 프론트 · 백엔드 스캐폴딩, 공통 레이아웃(Sidebar · TopBar), 공통 응답 · 예외, DB 마이그레이션 V1(DDL 기준), 환경변수(`.env.example`), 배포 설정 체크리스트, 기본 데이터(FR-DATA-003).
3. **쪼개기**: 기본 단위는 FR 하나 또는 화면 하나. 크면 수직으로(백엔드 API → 화면 연결), 너무 작으면(문구 하나) 같은 화면 이슈에 합친다. 업무 코드가 같으면 한 사람이 이어 맡기 좋게 묶는다.
4. **순서**: 요구사항 명세서의 '의존성' 칸을 선행 이슈로 옮긴다. P1 → P2 → P3. 순환이 생기면 API 계약으로 끊는다.
5. **계약 · 소유**: 다른 이슈를 부르는 곳은 계약 `C1…`(API 경로 · 입력 · 출력)로 적는다. 폴더 · 파일마다 소유 이슈를 하나로 정하고, 겹치면 `⚠ 겹침`.
6. **이슈 md 작성**: `docs/issues/NN_짧은제목.md` (NN = 착수 순서). 내용은 `.github/ISSUE_TEMPLATE/feature.yml`의 칸 순서를 따른다:
   기획 근거 · 우선순위 · 영역 · 선행 이슈 · 브랜치(`feat/NN-영문`) · 구현 범위(포함/제외) · 담당 파일 · 화면 · 연결(API) · 완료 조건(체크박스) · 테스트 항목(정상/예외) · 남은 [?]
   제목은 `[FR-XXX-000] 한국어 제목`. 라벨 제안: 종류 + P + 영역 + 업무 코드.
7. **작업분배표**: `docs/issues/작업분배(YYYY-MM-DD).md`에 이슈 목록 표(번호 · 제목 · ID · P · 선행 · 담당[?] · 브랜치), 착수 순서(동시에 할 수 있는 묶음), 담당 묶음 `[제안]`, 계약 목록, 파일 소유표와 `⚠ 겹침`, 기획 보완 필요 · 문서 충돌 · `[제안]` 목록.
8. **GitHub 등록은 사용자가 요청할 때만.** 목록을 먼저 보여 주고 승인받은 뒤 `gh issue create --title … --body-file … --label …`. 실제 번호가 초안 번호와 다르면 작업분배표에 대응표를 남긴다.

## 자체 점검

- [ ] 범위 안의 P1 기능이 모두 어느 이슈에 들어갔다 (빠진 FR 목록 보고)
- [ ] 모든 이슈에 FR/POL/화면 ID가 있다
- [ ] 완료 조건이 문서에서 왔고 확인 가능한 문장이다
- [ ] 선행 이슈에 순환이 없다
- [ ] 폴더 · 파일 소유 이슈가 하나다 (아니면 `⚠ 겹침`)
- [ ] #01에 환경 설정 체크리스트와 기본 데이터가 있다

## 끝낸 뒤 보고

이슈 개수(P1/P2/P3), 첫 착수 묶음, `⚠ 겹침` 수, 담당 미정 수, 기획 보완 필요 항목을 짧게 알리고 "이슈 번호를 crm-issue-coder에 넘겨 구현하세요"로 마친다.
