# 이슈 하나 구현하기 (돌아올개 CRM)

규칙의 기준은 `CONTRIBUTING.md`와 `CLAUDE.md`다. 이슈 범위 밖은 건드리지 않는 것이 이 스킬의 핵심이다.

## 1. 이슈 읽기

- `gh issue view <번호>` 또는 `docs/issues/NN_*.md`를 읽는다.
- 기획 근거의 ID를 문서에서 찾아 읽는다: FR은 요구사항 명세서, POL은 정책 정의서, 화면은 업무 분석, 테이블은 DB 설계.
- 다음 중 하나라도 있으면 **코드를 쓰기 전에 멈추고 사용자에게 묻는다**:
  - 선행 이슈가 아직 머지되지 않았다
  - 완료 조건이 비었거나 문서와 다르다
  - 정책 숫자 · 문구가 문서에 없다 (지어내지 않는다)
  - 다른 이슈 담당 파일을 고쳐야 한다

## 2. 브랜치

```bash
git fetch origin
git switch -c feat/<번호>-<영문-요약> origin/main   # 버그면 fix/
```

이미 이슈에 브랜치 이름이 있으면 그 이름을 쓴다.

## 3. 구현

- 이슈의 '담당 파일 · 화면' 안에서만 고친다. 폴더 구조는 `frontend/README.md`, `backend/README.md`를 따른다.
- 이름은 문서와 맞춘다: 테이블 · 컬럼은 DB 설계, 컴포넌트는 피그마 컴포넌트 이름, 패키지는 업무 코드.
- 숫자는 설정 테이블에서 읽고, 화면 문구는 정책 정의서 4장을 그대로 쓴다.
- 권한이 있는 기능은 서버에서도 막는다. 시간 계산은 Asia/Seoul.
- 공용 파일은 추가만 한다. 바꿔야 하면 이유를 메모해 PR에 적는다.
- DB 변경은 `backend/src/main/resources/db/migration/`에 번호를 올린 새 파일로.

## 4. 확인

- 빌드와 테스트를 돌린다 (명령은 `CLAUDE.md`의 '명령어').
- 이슈의 완료 조건을 하나씩 확인하고, 테스트 항목(정상 · 예외)을 테스트 코드나 수동 확인으로 남긴다.
- 확인하지 못한 항목은 숨기지 않고 PR에 "확인 못 함"으로 적는다.

## 5. 커밋 · PR (사용자가 시킬 때)

- 커밋: `feat: 한국어 요약 (#번호)`. 한 커밋에 한 가지 일.
- PR 전에 `git merge origin/main`으로 main을 합치고 충돌을 푼다.
- PR 제목은 커밋 형식, 본문은 `.github/pull_request_template.md`를 채운다. `Closes #번호`, 기획 근거 ID, 바뀐 파일, 스크린샷 자리, 체크리스트.
- `main`에 직접 push하지 않는다. 머지는 리뷰 승인 뒤 사람이 한다.

## 끝낸 뒤 보고

바뀐 파일, 완료 조건별 결과(통과 / 확인 못 함), 공용 파일 변경 여부, 발견한 기획 빈칸을 짧게 알린다.
