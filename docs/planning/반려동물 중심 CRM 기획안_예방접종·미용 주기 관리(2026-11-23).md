동물병원·미용 고객 데이터의 중심을 보호자가 아닌 반려동물에 두고, 아이마다 다른 예방접종·미용 주기를 자동으로 계산해 재방문을 관리하는 CRM을 만든다.

결제는 보호자가 하지만, 언제 다시 와야 하는지는 반려동물의 나이·품종·털 유형이 정한다. 그래서 고객 카드의 주인공을 반려동물로 바꾼다.

> 발표용 한 줄: 차트는 병원에 온 환자를 기록하고, 우리 CRM은 다시 와야 할 날이 지났는데 안 온 아이를 찾아 준다.

범위: 예방접종(심장사상충·구충 예방약 포함)과 미용 주기 관리, 강아지만. 노령견 케어 예측, 사료 교체 추천, 고양이는 다루지 않는다.

모듈 3 프로젝트 (TypeScript + Next.js), 12/4 배포 마감, 12/11 발표.

## 1. 문제

병원과 미용실은 고객을 보호자(전화번호) 단위로 관리하지만, 다시 와야 할 시점은 반려동물마다 달라서 재방문 시기를 놓친다.

- 예방접종은 어린 시기 기초접종과 이후 정기 추가접종처럼 나이에 따라 일정이 다르다.
- 미용 주기는 품종과 털 유형에 따라 몇 주 단위로 달라진다.
- 한 보호자가 여러 마리를 키우면 아이마다 일정이 겹치고 엇갈려 관리가 더 어렵다.
- 결과적으로 반려동물은 예방 공백이 생기고, 병원은 반복 방문과 단골을 잃는다.

문제 정의 한 문장: \[동물병원·미용 데스크\]는 \[반려동물마다 다른 접종·미용 주기를\] \[보호자 단위로만 관리해서\] \[재방문 시기를 놓친다\].

## 2. 대상

주 사용자는 미용을 함께 하는 동네 동물병원의 데스크 직원이고, 미용사가 기록을 남기고 원장이 결과를 본다. MVP는 병원 직원만 쓰며, 미용 중심 펫샵은 확장 대상으로 둔다.

| 구분 | 누구 | 이 CRM으로 하는 일 |
| --- | --- | --- |
| 주 사용자 | 데스크 실장·직원 | 오늘 접종·미용 시기가 된 아이와 누락된 아이 확인, 보호자 연락 결과 기록 |
| 기록 입력자 | 미용사 | 미용 기록 입력 (개인 미용 주기와 통합 타임라인의 재료) |
| 의사결정자 | 원장 | 재방문율, 접종 누락 현황, 연락 효과 확인 |
| 확장 대상 | 미용 중심 펫샵 | 미용 주기 관리만 사용 |
| 간접 수혜자 | 보호자·반려견 | 접종·미용 시기를 놓치지 않음. 데스크가 보여주거나 출력한 아이 일정 요약을 받음 (보호자 화면은 v2) |

수의사의 진료 업무는 대상에서 제외한다. 진료는 기존 차트 프로그램의 영역이다.

| 동물병원 차트(EMR) | 진료·접종 기록, 예약, 재진 관리. 연동 보호자 앱으로 방문 예정일 알림 | 진료 건 |

| 보호자 스스로 | 달력 앱, 수첩으로 일정 관리 | 보호자 |

## 4. 불편

기록이 보호자와 진료 건 단위로 흩어져 있어서, 반려동물 한 마리의 "다음 방문일"을 아무도 계산하지 않는다.

1. **아이별 주기가 안 보인다.** 같은 보호자의 두 마리가 접종일·미용일이 달라도 한 고객으로 묶여 구분이 안 된다.
2. **주기를 일괄로 잡는다.** 품종·털 유형과 무관하게 같은 간격으로 안내하거나, 아예 안내하지 않는다.
3. **접종과 미용 기록이 따로 논다.** 접종은 차트, 미용은 장부라 한 아이의 전체 이력이 안 보인다.
4. **누락과 효과를 모른다.** 시기가 지났는데 안 온 아이가 몇인지, 연락하면 몇 명이 돌아오는지 숫자로 볼 수 없다.

## 5. 개발할 부분

반려동물 프로필을 중심에 두고, 접종·미용의 다음 예정일을 자동 계산하는 기능 4개와 보호자에게 건네는 아이 일정 요약 리포트를 MVP로 만든다.

| 기능 | 해결하는 불편 | 주요 화면 | 측정 지표 |
| --- | --- | --- | --- |
| 반려동물 프로필 | 1. 아이별 주기가 안 보임 | 필수: 이름, 생년월일, 품종, 털 유형, 보호자 전화번호. 보호자 1명에 여러 마리 연결, 가족 보조 연락처 1개 | 보호자당 반려동물 수 |
| 주기 자동 계산 | 2. 주기를 일괄로 잡음 | 접종은 나이 구간 규칙, 미용은 그 아이의 실제 방문 간격으로 다음 예정일 계산 | 예정일 대비 실제 방문 차이(일) |
| 아이별 통합 타임라인 + 연락 기록 | 3. 기록이 따로 놂 | 접종·미용 이력 한 화면. 연락 결과를 예약함 / 전화 안 받음 / 거절 / 다른 병원 다님 / 번호 오류 중 하나로 기록 | 연락 결과 유형별 재방문 전환율 |
| 재방문 대시보드 | 4. 누락과 효과를 모름 | 오늘·이번 주 대상 아이 목록, 누락 아이, 서비스별 재방문율, 연락 결과 유형별 전환율 | 접종 누락률, 미용 재방문율 |
| 아이 일정 요약 리포트 | 1·3. 보호자도 아이별 일정을 모름 | 한 아이의 접종·미용 이력, 다음 예정일, 연락 기록을 한 장으로. 화면에 띄우거나 출력해 건넴 | (지표 없음) |

**데이터 구조:** 보호자(1) → 반려동물(N) → 방문 이력(N). 다음 예정일은 반려동물 단위로 계산하고, 연락은 보호자 단위로 묶어서 한 번에 안내한다.

**주기 규칙:** 접종은 나이 구간별 일정, 미용은 그 아이의 실제 미용 기록으로 계산한다. 기본 간격은 규칙 표로 두고 병원이 수정할 수 있게 한다. 개인 미용 주기 계산 방법은 정책 정의서에서 정한다.

**누락 기준:** 개인 예정일 + 14일이 지나도 방문이 없으면 누락 (14일은 병원 설정값).

**범위에서 빼는 것:** 진단, 처방, 수납, 예약 시스템(예약은 기존 차트, CRM에는 연락 결과 '예약함'만), 노령견 케어 예측, 사료 교체 추천, 고양이, 실제 문자 발송(버튼만 두고 모의 처리).

**v2:** 미용 중 발견한 이상 → 진료 연결, 노쇼 빈자리 연결, 보호자용 아이별 일정 화면.

**더미 데이터:** 보호자 300명 안팎, 반려동물 400마리 안팎을 품종·나이 분포를 섞어 생성하고, 주기 규칙에 일부러 누락·지연을 섞어 분석이 의미 있게 만든다.

**기술:** TypeScript + Next.js, Vercel 배포. Spring + MySQL 연동 예정 (팀 확정 전, 배포 위치 미정).
