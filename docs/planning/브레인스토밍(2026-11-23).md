동물병원 데스크 실무자가 겪는 불편 40개를 모으고, 하나씩 MVP·v2·해결 안 함으로 골라 재방문 CRM의 범위를 좁혔다. 결과는 MVP 16개, v2 3개, 해결 안 함 18개, 직접 입력 2개, 판단 빈칸 1개다.

## 1. 출발 질문

- 반려동물마다 다른 접종·미용 주기를 데스크가 기억 대신 목록으로 챙길 수 있을까?
- 보호자에게 한 연락이 실제 재방문으로 이어졌는지 숫자로 볼 수 있을까?
- 실무자 불편 중 어디까지가 우리 CRM의 일이고, 어디부터가 기존 차트·현장의 일일까?

## 2. 판단 기준 (아이디어를 좁힌 방법)

| 기준 | 질문 | 이 경우 |
| --- | --- | --- |
| 재방문과 이어지나 | 접종·미용 주기, 연락, 재방문율과 직접 이어지는가 | 해결 후보 |
| 진료·수납·예약 영역인가 | 진단·처방·수납·견적·예약 시스템의 일인가 | 해결하지 않음 |
| 12/4까지 만들 수 있나 | 3주 안에 가능한가, 다른 기능이 먼저 있어야 하나 | 어려우면 v2 |

## 4. 백로그에서 새로 나온 아이디어 (후속 안건)

문제 카드에 적힌 메모에서 원래 기획에 없던 기능이 나와, 후속 안건으로 따로 정했다.

| 안건 | 나온 곳 | 아이디어 | 결정 |
| --- | --- | --- | --- |
| R1 | G1, H3, B4 | 보호자용 리포트를 넣을까 | MVP에는 '아이 일정 요약' 한 장만, 나머지는 v2 |
| R2 | G1, H3, B4 | 리포트에 무엇을 담을까 | 지난 이력, 다음 예정일, 연락 기록 요약, 수의사 상담 내용, 홈케어 안내 |
| R3 | - | 리포트를 어떻게 건넬까 | 데스크 화면에서 띄워 보여주거나 출력 (논의 중) |
| R4 | G1, H3, B4 | 세 카드의 판단 정리 | R1 결과를 따름 |
| N1 | F4 | 리뷰·상담 기록을 모아 개선 방향 주기 | 대시보드 연락 결과 통계로 대신·리뷰 분석은 v2 |
| C1 | A4, A5 | 데려온 사람 번호 처리 | A5 내용을 A4로 옮김 (그날 방문 기록에만 남김) |
| C2 | D4 | '등록 여부만 확인'의 뜻 | 반려동물 정보에 '펫보험 가입 여부' 칸 (선택 입력) |
| D1 | A2 | 사진·등록번호를 MVP에 | 둘 다 MVP, 보호자가 사진을 거절하면 넣지 않음 |
| D2 | B1 | 털 유형·품종 선택지, 대략 나이 | 털 유형·품종은 선택지로 입력 |
| D3 | E3 | 신입 안내 | 화면마다 한 줄 안내만 MVP, 온보딩 자료는 v2 |
| D4 | D2 | 미용 패키지 방식 | v2 시작할 때 정함 |

## 5. 키워드

- **재방문:** 개인 예정일, 누락, 재방문율, 연락 후 전환율
- **주기:** 접종 일정, 심장사상충·구충, 개인 미용 주기(실제 방문 간격)
- **보호자·아이:** 다두 가구 묶음 연락, 통합 검색, 중복 경고, 무지개다리
- **연락:** 결과 유형 버튼, 선호 연락 방법, 주의 태그, 통화한 사람, 다음 연락 예정일
- **보호자에게 건네는 것:** 아이 일정 요약 리포트
