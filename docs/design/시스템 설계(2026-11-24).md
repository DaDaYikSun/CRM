## 1. 시스템 개요

돌아올개는 반려견마다 다른 접종·미용 예정일을 계산해, 다시 올 때가 지난 아이를 데스크가 찾아 연락하고 그 연락이 재방문으로 이어졌는지 숫자로 보는 동물병원 직원용 웹 서비스다.

Next.js 프론트엔드, Spring Boot 백엔드, MySQL 데이터베이스로 구성된 3계층 아키텍처를 사용한다. 진료·수납·예약은 기존 동물병원 차트(EMR)의 영역이라 만들지도, 연동하지도 않는다. 보호자 화면은 v2다.

## 2. 기술 스택

| 구분 | 기술 |
| --- | --- |
| Frontend | Next.js (App Router), TypeScript |
| Backend | Spring Boot (REST API) |
| 인증·보안 | 아이디·비밀번호 로그인, BCrypt 해시, 역할 기반 권한, 서버 세션 (Spring Session) |
| Database | MySQL 8.0 (8.0.16 이상, InnoDB, utf8mb4) |
| DB 마이그레이션 | 번호 붙인 SQL 파일 (`V1__init.sql`~), Flyway 권장 |
| 빌드·테스트 | GitHub Actions 권장 (PR마다 빌드·테스트) |
| 배포 | Railway (Next.js · Spring Boot · MySQL 모두) |
| 외부 연동 | 문자 발송은 모의 처리 (실제 발송 없음) |

버전은 공통 기반 이슈(#142)에서 정했다: Java 21, Spring Boot 3.4, Next.js 15, React 19, TypeScript 5 (`backend/build.gradle`, `frontend/package.json`).

## 3. 시스템 구성 및 데이터 흐름

```
직원 브라우저 (크롬, PC·태블릿)
   │ HTTPS
   ▼
Next.js Frontend [Railway]
   │ REST API (JSON), Next.js rewrites로 같은 출처 호출
   ▼
Spring Boot Backend [Railway] ─── MySQL 8.0 [Railway]
   ├── 업무 모듈 (고객 · 방문 · 주기 · 연락 · 대시보드 · 백오피스)
   └── 문자 발송 (모의, 실제 서비스로 교체 가능하게 분리)
```

- **Frontend:** 화면 렌더링, 사용자 상호작용, 화면 단 권한 처리(메뉴 숨김). 리포트는 새 탭에서 브라우저 인쇄로 A4 출력. 백엔드 API는 Next.js rewrites로 같은 출처처럼 호출
- **Backend:** 예정일 계산, 누락·전환 판정(누락은 판정할 때 결과를 저장하고 목록·통계는 저장된 값만 읽음. 판정은 매일 0시(한국 시간) 판정 작업, SYS-ARC-07), 권한 검사, 기록 저장, 대시보드 집계
- **Database:** 보호자, 반려동물, 방문 기록, 예정 일정, 연락 기록, 규칙·설정값, 변경 이력 저장
- **설정값:** 누락 기준(14일), 연락 보류(30일), 미용 기본 간격, 접종 규칙은 코드가 아닌 DB 설정 테이블에서 읽는다
- **캐시:** 별도 캐시 서버 없이(제안), 연락 대상 목록에 필요한 값만 저장할 때 미리 계산해 둔다

**핵심 업무 흐름**

```
보호자·아이 등록
   ▼
접종·미용 예정일 자동 계산
   ▼
연락 대상 목록 (오늘 / 이번 주 / 누락)
   ▼
연락 결과 기록 (예약함 · 전화 안 받음 · 거절 · 다른 병원 다님 · 번호 오류)
   ▼
방문 기록 → 예정 완료 + 다음 예정일 계산 + 재방문 전환 판정
   ▼
대시보드 (재방문율 · 접종 누락률 · 연락 효과)
```

## 4. 인증 및 보안

- 직원별 아이디·비밀번호 로그인 (공용 계정 없음)
- 비밀번호는 BCrypt 해시로 저장, 8자 이상 영문+숫자
- 로그인 8시간 뒤 자동 만료, 상단 [로그아웃] 제공 (서버 세션, 세션 ID는 HttpOnly 쿠키. 토큰을 브라우저 저장소에 두지 않음)
- 역할 3가지(관리자 · 데스크 · 미용사), 화면 숨김과 별개로 서버에서도 모든 요청의 권한 검증
- 목록·검색에는 전화번호 뒤 4자리만 노출, 전체 번호는 연락 패널·보호자 상세에서만
- 개인정보 수집·이용 동의, 안내 문자 수신 동의를 등록 때 받아 저장
- 모든 기록·규칙 변경에 기록한 직원·시간 자동 저장, 이력은 추가만 가능
- 기록은 실제로 지우지 않고 상태값으로 표시 (퇴사 직원 비활성화, 무지개다리 표시)
- 비밀번호·키·`.env`는 저장소에 올리지 않고 환경 변수로 관리
- 시연에는 실제 개인정보 없이 더미 데이터만 사용
