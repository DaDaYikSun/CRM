## 1. 읽는 법

- **표 형식:** 시스템 설계 7장과 같은 `ID | 항목 | 내용 | 결정 상태 | 근거 | 비고`다 (#63). `TKN-…`(토큰), `CMP-…`(컴포넌트) 번호는 이 문서 안에서만 쓴다. 이슈 · 커밋 · 코드 주석에는 FR / NFR / POL ID를 쓴다.
- **결정 상태:** 확정 / 제안(팀 확인 전 권장안) / 미정.
- **토큰 기준 (2026-11-25 결정):** 우리 서비스 색은 **파랑 계열**이다. 화면 프로토타입에 실제로 쓴 파랑 계열 색 값을 `frontend/README.md`의 이름 규칙(`--navy-900`, `--peri-500`, `--spacing-16`)으로 정리했다. 피그마 변수와 이름 · 값이 같은지는 아직 대조하지 못했다(이 세션에서 피그마를 열 수 없음). 그래서 토큰 이름은 '제안'이고, 피그마와 대조한 뒤 확정한다 (7장 1번).
- **쓰지 않는 것 (2026-11-25 결정):** 프로토타입의 '디자인 시스템' 보드와 `theme.css`(주황 · 갈색 "강아지 앱 톤")는 쓰지 않는다. 실제 화면에 적용되지도 않았다. 역할 토큰의 이름 구조(`bg-page`, `text-muted`, `status-danger-bg` …)만 빌려 썼다.
- **컴포넌트 이름:** `frontend/README.md`에 이미 나온 9개(Button, Badge, CautionTag, ResultButton, TargetRow, StatCard, TimelineItem, Sidebar, TopBar)는 피그마 이름이라 '확정'이다. 그 밖의 이름은 '제안'이고 피그마 02 Components와 대조해 맞춘다.
- **화면 문구:** 컴포넌트에 들어가는 문구는 정책 정의서 4장을 그대로 쓴다. 컴포넌트가 문구를 새로 짓지 않는다.

## 3. 공용 컴포넌트

**어디에 두나 (제안):** 두 화면 이상에서 쓰는 범용 부품은 `components/ui`, 화면 틀은 `components/layout`, 한 업무에서만 쓰는 부품은 `features/<업무>/`에 둔다. README에 이미 나온 9개는 `components/ui` · `components/layout` 그대로 둔다.

props 표기: `이름: 값 / 값` (값 중 하나), `?`는 없어도 되는 값.
