## 3. 담당 묶음 [제안]

팀 4명 누구도 '프론트엔드 개발' · '백엔드 개발'로 정해져 있지 않다. 그래서 개발 영역이 아니라 **업무 영역과 원래 역할의 자연스러운 쪽**으로 묶었다. 모두 `[제안]`이고, 담당은 팀이 정한다 (한 이슈 한 사람).

| 사람 (역할) | 묶음 [제안] | 이유 |
| --- | --- | --- |
| 이종민 (형상관리) | #01, #02, #09, #14, #17, #18, #33, #34 | 저장소 뼈대 · 공용 파일(layout · ui · common)과 계정 · 권한 · 공통 화면(AUTH · ADM 계정 · COM). 공용 파일 리뷰를 어차피 맡음 |
| 신아림 (DBA) | #03, #06, #11, #15, #16, #25, #26, #32, #35 | 쿼리 · 계산이 무거운 쪽 (schedule · 지표 · 규칙 · 더미). #01의 V1 마이그레이션 · 시드 리뷰 |
| 류다연 (PM) | #04, #05, #08, #10, #19, #21, #22, #27, #31 | 스프린트 1 화면(등록 · 검색 · 상세)과 고객 관리 · 리포트(CUS · SRCH · RPT). 사용성 테스트 시나리오와 맞닿음 |
| 양다연 (도메인 전문가) | #07, #12, #13, #20, #23, #24, #28, #29, #30 | 결과 유형 · 전환 · 문자 같은 도메인 규칙이 많은 쪽(VIS · CNT). 단 11/27까지는 #8 접종 규칙 표 확정이 먼저라 스프린트 1에는 #07만 |

- 이슈 수: 8 · 9 · 9 · 9. 담당 미정 35개 (모두 `[?]`).
- 같은 업무 코드는 한 사람이 이어 맡도록 묶었다 (customer → 류다연, contact → 양다연, admin 계정 · auth → 이종민, cycle · target · dashboard → 신아림). 예외: #25 · #32(admin 패키지)는 규칙 데이터라 신아림, #31은 리포트라 류다연, #30은 문자라 양다연 → admin 패키지 ⚠ 겹침.

## 6. 기획 보완 필요 · 문서 충돌 · [제안]

### 기획 보완 필요

1. **미용사 첫 화면**: 팀 결정은 S-11 미용 탭(직원 앱 안 탭, 다른 메뉴 잠금 · 비활성). 문서는 S-05 통합 검색 — FR-AUTH-001 상세 · 확인 방법, POL-ACC-007, 업무 분석 - 사용자 1장 · 2-0 · 2-6 · 5장, 요구사항 5-1 V12. → #02 · #14
